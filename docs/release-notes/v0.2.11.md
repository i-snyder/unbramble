`unbramble stats` now reads counts and coverage from the committed index. On a cold project, `stats --json` returns an `indexState` such as `missing` or `incomplete` and omits counts. Scripts that need current counts on the first call should use `stats --refresh --json`. The `--collisions` and `--unresolved` reports also check freshness.

`unbramble watcher-status --json` now distinguishes a foreground index writer, a watcher starting its first index, and a watcher with a verified heartbeat. Startup reports the worker's PID as soon as it is available.

Polling watcher status during startup no longer causes the new worker to exit before indexing. Automatic watcher launch also has a bounded wait so a restricted Windows host can return a completed query or stats summary even when it blocks the launch.
